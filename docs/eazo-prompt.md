## 第一段：主提示词

请为我构建一款移动端优先的 AI 护肤学习 App：**SkinPilot AI**。

### 1. 定位
这不是护肤品推荐 App，也不是普通聊天机器人。核心使命：解决用户从“看过护肤教程”到“真正学会并独立完成护肤流程”之间的断层。
把 TikTok、YouTube、小红书上碎片化的教程，转化为个性化、可执行、可跟练、可复用的流程。
目标用户：护肤新手、轻度进阶用户、经常看教程但缺少实际操作的年轻人。
不做：医疗诊断、皮肤病治疗、美容院功能、根据自拍给出确定的医学结论。

### 2. 核心闭环
**Watch → Understand → Personalize → Practice → Complete → Review → Reuse**
优先做完这一条真实可用的路径：导入教程 → AI 拆解 → 个性化 → 逐步跟练 → 理解测试 → 保存流程。

### 3. 页面（共 7 个）
1. **Onboarding**：肤质（干性/油性/混合性/中性/不确定）、敏感情况、护肤目标、预算（AUD）、护肤经验、当前拥有的产品（手动添加：名称、类型、成分），并选择 AI 导师。
2. **Home**：个人护肤学习中心，显示导师、最近流程、“导入新教程”“一键重新开始”。
3. **Import Tutorial**：三个入口——上传视频（≤100MB、≤10 分钟）、粘贴公开视频链接（仅在合法且技术允许时获取内容）、上传截图或文字说明。
4. **AI Analysis**：展示结构化教程。每个步骤含：操作说明、注意事项、来源时间戳、完成条件。
5. **Guided Practice**：沉浸式逐步跟练（重点页面）。
6. **My Routine**：保存的个人流程，可一键重新开始。
7. **Progress**：学习 Dashboard。

### 4. AI 解析规则（Feature 1）
- 输出步骤、产品名称与类型、使用顺序、操作方法、注意事项、关键时间节点。
- **必须区分“视频明确出现”与“AI 推断”**，两者用不同标签显示。
- 不允许编造产品、品牌、成分或操作；没有时间戳就留空。

### 5. 个性化（Feature 2）
根据肤质、敏感程度、预算、已有产品调整教程。每一步给出：使用已有产品 / 预算内的类别替代 / 暂时不需要购买 / 调整后的顺序。
例：原教程用高价精华而用户预算只有 30 AUD，则标为“可跳过”并说明原因。
没有经过验证的商品数据时，不显示价格、库存、成分或购买链接，只推荐产品类别。
基础成分冲突提醒：例如维 A 类与酸类/过氧化苯甲酰同用时提示刺激风险，并注明“基础规则，非完整成分库”。

### 6. Guided Practice 交互（Feature 3）
每一步显示：当前该做什么、如何操作、预计时长（带计时）、常见错误。
底部五个按钮，名称用英文原文：
- **I've done it**
- **I don't understand**
- **Why this step?**
- **Can I skip this?**
- **What if I don't have this product?**
AI 的回答必须基于当前步骤和用户资料，不是通用聊天；简短（80 字内）；遇到疼痛、红疹、灼烧时建议停用并咨询医生或药师。
“I don't understand”要自动记入用户的困难列表。

### 7. AI 导师形象
做两个可选的虚拟导师，插画风格、气质高级：
- **Leo**：年轻男性，干净利落的短发，白色护理外套，沉稳友好。
- **Mia**：年轻女性，柔和的及肩长发，白色护理外套，温和亲切。
都是原创虚拟形象，**不得模仿任何真人或名人**。导师会眨眼；说话时嘴部有动画；跟练页以头像加对话气泡的方式出现，而不是聊天窗口。

### 8. 可信知识库（Feature 4）
用 RAG 约束 AI 导师。来源优先：AAD（美国皮肤科学会）、FDA、中国国家药监局 NMPA、DermNet、同行评审文献、产品官方成分与使用说明；电商销量评价与博主推荐可作为参考，但必须标明属于创作者经验或市场口碑，不能当作科学证据。
每条关键建议尽量显示：Reference、Source URL、Evidence level、更新时间、简要解释。
证据等级固定四档：**有充分证据支持 / 证据有限 / 仅来自视频创作者的个人经验 / 暂无可靠依据**。
知识库无法支持某个结论时，明确说“不确定”。**严禁虚构文献、来源或置信度。**
知识库尚未接入的阶段，页面上必须显示“证据：演示占位”，不得出现看起来像真实的引用。

### 9. 学习闭环与 Dashboard（Feature 6）
完成教程后：2 道理解题（由 AI 基于已保存步骤生成，不引入步骤外的知识）→ 用户如实选择“照着教程做的 / 不看教程独立完成”→ 记录遇到的困难 → 保存流程。
**完成度分三档，不得把点击“完成”等同于掌握：**
- 自报完成
- 理解测试通过（题目全对）
- 独立复现（题目全对 **且** 用户确认未看教程）
Progress 页显示：**Tutorials Learned、Routines Completed、Independent Completion Rate、Learning Progress、Common Difficulties**。独立完成率只统计“独立复现”。

### 10. 视觉与体验
关键词：Apple-like minimalism、Premium skincare aesthetic、Clean typography、Soft neutral colors、Smooth micro-interactions、AI-native interface、Mobile-first。
具体：浅灰白背景（#F5F5F7 一类）、大标题加大留白、28px 左右大圆角卡片、柔和阴影、底部毛玻璃导航栏、单一冷青色强调色、黑色药丸按钮；支持深色模式与 reduced-motion。
避免传统电商界面，不要做成聊天机器人界面。

### 11. 技术与数据
- 移动端友好的 Web App/PWA；架构模块化，便于以后迁移到 React Native。
- 所有 AI 调用必须在服务端，不暴露 API Key。
- 视频处理为异步任务，限制大小、格式与成本。
- 数据表：profiles、user_products、tutorials、tutorial_steps（含 source: explicit/inferred、timestamp）、routines、practice_sessions（completion_level: self_reported/quiz_passed/independent）、kb_documents（含 evidence_level、source_url、updated_at）。用户数据按用户隔离（行级权限）。
- 邮箱登录。

### 12. 开发原则（请严格遵守）
1. MVP First：先验证用户能否真正学会并完成流程。
2. **No Fake Data**：所有演示数据必须明确标注“演示数据”，不得冒充真实分析、真实来源、真实价格。
3. Evidence Based、Privacy First、Safety First（不做医学诊断，避免危险成分组合）。
4. 暂时无法实现的功能（视频解析、真实知识库、摄像头实时指导），用清楚标注的占位，不要伪装成已完成。
5. 完成后请告诉我：哪些功能真实可用，哪些仍是模拟。

## 第二段：追加提示词（按需）

**A. 视觉打磨**
请把整体视觉再提升一档：参考 Apple 官网的版式节奏，首页用大号标题和导师头像做主视觉；导师头像要更精致，有柔和渐变背景和轻微光晕；跟练页要有沉浸感，一屏只显示一步。保持留白，不要堆叠卡片。

**B. 真实解析**
把“导入教程”接成真实功能：用户粘贴文字说明后，服务端调用 AI，按固定 JSON 结构输出步骤（title、category、instruction、caution、timestamp_sec、source=explicit/inferred、optional），并用结构校验。没有依据的字段留空，不得编造。

**C. 知识库**
接入知识库，并先让我提供资料。每条建议显示来源名称、链接、证据等级、更新时间。没有检索到依据时，显示“暂无可靠依据”。

**D. 演示准备**
增加一个“演示数据”开关，开启时所有演示内容带明显标签；准备一套 3 分钟演示流程：选导师 → 导入 → 个性化 → 跟练 → 理解测试 → Progress。
